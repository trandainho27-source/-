# 支付接入契约

## 当前状态

在线支付默认关闭。`POST /api/payments/create` 验证订单访问凭证后，返回 HTTP 503 与中文未接入说明。页面不提供伪二维码，不自动把点击按钮当成付款。

后台的店主可以在核对线下到账后输入收款流水号和依据，调用同一事务交付流程。运营、客服无确认收款权限。后台登记退款只是记账，先在支付平台完成实际退款。

## 正式支付适配需要实现

1. 选择持牌支付服务及商户账户，申请微信 / 支付宝的对应商户能力。
2. 在 `payments/create` 中基于服务器订单金额创建支付。返回真实支付链接或二维码，限制订单仍为未过期的 `pending`。
3. 实现对应服务商的官方通知验签、证书更新、金额与币种校验。
4. 验签后调用 `settleOrder`，传入服务商 ID、全局唯一交易流水、金额（整数分）。
5. 对过期后到账的订单走人工核对 / 退款流程，避免库存已释放后自动发货。
6. 实现退款 API、退款通知与对账任务，并与店主权限和审计日志连接。

所有密钥只放 Cloudflare Secrets；后台设置接口不接受支付密钥。

## 已提供的自定义 HMAC 协议

这是给自定义适配层使用的协议，**不是微信或支付宝的官方通知协议**。默认关闭。

配置 `PAYMENT_PROVIDER=custom-hmac`，并将 `PAYMENT_WEBHOOK_SECRET` 设置为随机 Secret，才会启用 `/api/payments/webhook`。开启回调不会自动启用支付下单，`paymentEnabled` 仍为 false，直到下单适配完成。

请求体：

```json
{"orderId":"CQ...","status":"paid","currency":"CNY","amount":3900,"transactionId":"provider-unique-id"}
```

- `amount` 为整数分，必须等于订单金额；金额始终由服务器计算。
- `x-payment-timestamp`：当前 Unix 秒，10 位数字，允许前后 300 秒。
- `x-payment-signature`：小写十六进制 HMAC-SHA256；签名数据为 `${timestamp}.${rawBody}`，使用原始请求体字节，不能先解析再重新序列化。
- 无效签名返回 401，金额或内容不符返回 400，订单已过期 / 流水冲突返回 409。
- 同一订单、同一提供方和同一流水的重复成功通知幂等；同一提供方的流水不能用于另一个订单。
- 卡密分配、已交付状态、订单状态及审计日志在同一 D1 batch 事务中完成。

对账职责仍由适配层承担：真实到账真实性、支付机构通知规范、用户支付页面、结算与实际退款。
